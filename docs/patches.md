# Patches

This repo has two builds:

- **Production build** (`image-main/`): the vLLM main nightly at commit `7f1a5398e9` plus our 18-patch series and the two FlashInfer GB10 fixes, with an optional NCCL build. This is the image we serve, launched with `launch/launch_node.sh`.
- **Release build** (`image/`): stock vLLM v0.30.0 plus 13 vLLM patches and the same two FlashInfer patches. Kept for anyone who wants to stay on a vLLM release, launched with `launch/launch_node_v030.sh`.

## Production build: vLLM main nightly 7f1a (`image-main/`)

The base is `vllm/vllm-openai:nightly-7f1a5398e9610d96c473931a26c0e12bbe0d0423` (vllm 0.30.1rc1.dev48+g7f1a5398e). `image-main/build.sh` copies the target files out of that image, applies `patches/vllm/series` in order and then the FlashInfer patches, each with zero fuzz (`patch -F0`), and refuses to build unless every patched file matches `image-main/EXPECTED.sha256`, the checksums of the files in the image we serve. The image itself is a COPY-only layer over the base; no container runs during the build. The series touches 16 vLLM files and the FlashInfer patches 2 more, 18 files in all.

**Where they come from.** The numbered patches keep their numbers from the v0.30 series so the lineage stays readable. 01 to 08 are our ports of the GB10 changes in Tony's image and recipe ([tonyd2wild/GLM-5.3-Flash-NVFP4-1M-KV-4x-DGX-Spark](https://github.com/tonyd2wild/GLM-5.3-Flash-NVFP4-1M-KV-4x-DGX-Spark)), 09 is ours, 10 is our port of jnardiello's 8-bit drafter experiment, and each was checked against vLLM main before carrying it: most apply with the same changed lines as on v0.30, 03, 04 and 09 only needed new file paths, and 05 and 08 were re-ported (notes below). The `p` patches are new on this build. The `u` patches are upstream vLLM pull requests applied verbatim (vLLM's own hunks only). Several files take more than one patch (for example 04, 09, p2 and p4 all edit `common/model.py`), so the series must be applied in the order below.

### Notes on the re-ported and new patches

- **05.** vLLM main moved the kpool indexer into `nvidia/sparse_indexer.py` and routes decode top-k for both the kpool and the DSA indexers through one shared dispatcher (`indexer_topk.py`), so the old guard at the kpool call site no longer exists. The -1 initialization is carried onto the two remaining buffer allocations, and the small-SM guard now sits in the dispatcher itself, where every caller goes through it.
- **08.** On vLLM main, GLM-5-Next's KV groups are returned before vLLM's own EAGLE-group annotation runs, and neither of its rules matches a sliding-window drafter, so the patch marks the drafter's group itself. Our first port to vLLM main marked it unconditionally. With `disable_eagle_block_drop`, vLLM then wrote the KDA recurrent state at the last full block but kept it one block lower, where nothing was written, and resumed agent sessions lost their prefix cache: a cache-resume check on 6 resumed long-session prompts got 0 / 0 / 0 / 13824 / 13824 / 0 cached tokens instead of the release build's 18432 / 18432 / 18432 / 16128 / 16128 / 18432. Upstream only marks groups when the block drop is on, so the fix gates the flag on `use_eagle_block_drop()`. A CPU replay of vLLM's real scheduler and KV manager reproduced the broken numbers before the fix and the release build's after, and on hardware the fixed build matched the release build exactly (18432 / 18432 / 18432 / 16128 / 16128 / 18432).
- **p4.** vLLM main widened its block-FP8 attention loader to also treat names ending in `.weight_scale` as FP8 scales. NVFP4 checkpoints name their attention scales `weight_scale` too, so the helper buffered them as FP8 block scales and the NVFP4 attention projections never received theirs: a debug boot showed those layers' scales still NaN after loading. v0.30 only matched `weight_scale_inv`, which is why the release build loads fine without this patch.

### Optional NCCL build (`image-main/nccl/`)

NCCL v2.30.7-1, the version the 7f1a nightly bundles, plus [NVIDIA/nccl#2393](https://github.com/NVIDIA/nccl/pull/2393) (kodlan), an acquire fence in `ncclIbIsend`'s CTS poll. On Arm a weakly ordered load there can read a stale request count and hang a RoCE collective ([NVIDIA/nccl#2334](https://github.com/NVIDIA/nccl/issues/2334)). `nccl/build_nccl.sh` compiles it inside the base image for sm_121 only and writes `nccl/libnccl.so.2`; `NCCL_LIB=nccl/libnccl.so.2 ./build.sh` then puts it in the image. Our production image carries it. It fixes a hang, not speed.

### Not carried over from the release build

- **11-lmhead-w8a16:** tested on v0.30 and rejected (see the release build below).
- **12 and 13:** replaced by the upstream pull requests they were taken from (u58704 and u58454), which apply to vLLM main as they are.
- **14 ([vllm#57477](https://github.com/vllm-project/vllm/pull/57477), JaredforReal):** already in vLLM main.

### Serving config these patches assume

See `launch/launch_node.sh`: sparse MLA through the SM90 FlashInfer backend with fp8 KV cache, the NVFP4 MoE on `--moe-backend humming` ([Humming](https://github.com/vllm-project/humming) 0.1.16 from the base image, Apache-2.0), DFlash2 drafting up to 7 tokens with block verification and a per-batch-size draft length, `disable_eagle_block_drop`, `FULL_AND_PIECEWISE` CUDA graphs, `VLLM_MARLIN_USE_ATOMIC_ADD=1` and `VLLM_DRAFTER_W8A16=1`, and Z.ai's official 09-07 chat template plus one explicit thinking opt-out line (`template/chat_template_zai0907_optout.jinja`). How this build compares with the release build, including what it costs, is in the README and `docs/findings.md`.

## Release build: vLLM v0.30.0 (`image/`)

The image is stock `vllm/vllm-openai:v0.30.0` plus 13 vLLM patches and 2 FlashInfer patches (and one optional vLLM patch and an optional NCCL build). `image/build.sh` applies them and refuses to build unless every patched file matches `image/EXPECTED.sha256`, the checksums of the files in the image behind the published numbers.

**Where they come from.** Patches 01 to 08 port the GB10 changes from Tony's image and recipe ([tonyd2wild/GLM-5.3-Flash-NVFP4-1M-KV-4x-DGX-Spark](https://github.com/tonyd2wild/GLM-5.3-Flash-NVFP4-1M-KV-4x-DGX-Spark)) onto stock vLLM v0.30.0. Every change was checked against upstream first: whatever v0.30.0 already ships was dropped, the rest was ported and re-verified. Two problems found while booting the port were fixed in patches 07 and 08. The two FlashInfer patches are Tony's. Patches 09 and 11 are ours; 10 is our port of jnardiello's E22b 8-bit drafter experiment. Patches 12 to 14 backport three upstream vLLM fixes that landed after v0.30.0 (2026-09-25 update).
